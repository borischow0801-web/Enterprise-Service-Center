# 企业端 H5 UI 原型规则

## 目标

先把视觉方向沉淀为可执行的静态原型，再逐步接入真实业务。当前阶段只验证视觉、布局、移动端适配与交互层次，不改造接口、不替换现有业务页面。

## 设计关键词

- 清爽舒适：蓝天、白云、海风、浅色背景、留白充分。
- 沿海识别：云层、海浪线、海玻璃质感、轻微珊瑚色强调。
- 政务可信：信息层级清楚、对比度足够、按钮明确、状态可识别。
- 个性化：企业名称、待办摘要、服务建议、进度状态突出。
- 轻动效：只使用低干扰动效，例如云层漂移、按钮涟漪、卡片浮动、波纹高亮。

## 视觉系统

### 颜色

- 主色：`#1677ff`，用于主按钮、状态高亮、关键图标。
- 海面蓝：`#28b6f6`，用于渐变与辅助块。
- 天空浅蓝：`#eaf7ff`，用于页面背景。
- 云白：`rgba(255, 255, 255, 0.78)`，用于玻璃卡片。
- 深文本：`#123047`，用于标题。
- 次文本：`#5f7488`，用于说明。
- 珊瑚强调：`#ff8a6a`，用于“去评价”“紧急”“立即处理”等少量 CTA。
- 成功绿：`#25b97f`，用于可预约、已完成。
- 警示黄：`#f5a623`，用于待处理、提醒。

### 布局

- 页面容器宽度：`100%`，内容最大宽度建议 `480px`，居中。
- 页面左右边距：小屏 `14px`，常规屏 `16px`，大屏 `20px`。
- 卡片圆角：主卡片 `22px`，普通卡片 `18px`，按钮 `999px`。
- 卡片间距：`12px-16px`。
- 首屏应有明显的情绪化头部，但不得压缩核心入口。
- 业务页面优先展示筛选、摘要和主列表，不做纯装饰型大图堆叠。

### 字号

- 页面主标题：`24px-28px`。
- 分区标题：`16px-18px`。
- 卡片标题：`15px-17px`。
- 正文：`13px-14px`。
- 辅助说明：`11px-12px`。

### 组件

- 顶部问候/标题区：包含城市/服务中心、企业名或页面说明。
- 玻璃信息卡：用于摘要数据、服务入口和提醒。
- 业务卡片：承载诉求、会议室等核心对象。
- 状态标签：颜色清晰，文案短。
- 胶囊筛选：用于状态筛选、日期筛选、条件筛选。
- 浮动 CTA：只放一个主要动作，避免多个浮动按钮竞争。
- 底部导航：保留微信 H5 的轻量触达感，并注意安全区。

## 移动端适配规则

- 禁止用固定 `390px` 宽度实现页面主体。
- 使用 `width: min(100%, 480px)` 或类似方式限制大屏过宽。
- 使用 `clamp()` 控制字号和关键装饰尺寸。
- 所有横向卡片在小屏下必须允许横向滚动或自动换行。
- 长企业名、长诉求标题必须支持换行或省略。
- 底部固定按钮必须预留 `env(safe-area-inset-bottom)`。
- 顶部内容避免贴近刘海屏，预留 `env(safe-area-inset-top)`。
- 核心按钮点击区域建议不小于 `44px` 高。
- 不依赖 hover，所有交互以触摸为主。

## 静态原型范围

当前先做三个页面：

- `/ui-preview/home`：首页，展示企业问候、三大服务入口、待办摘要。
- `/ui-preview/appeals`：企业诉求列表，展示搜索、状态筛选、诉求卡片、评价入口。
- `/ui-preview/meeting-rooms`：共享会议室列表，展示筛选、可预约日期、会议室卡片、材料提醒。

## 验收方式

启动企业端 H5：

```bash
cd enterprise-h5
npm run dev
```

浏览器打开：

- `http://localhost:5174/ui-preview/home`
- `http://localhost:5174/ui-preview/appeals`
- `http://localhost:5174/ui-preview/meeting-rooms`

局域网设备访问时，将 `localhost` 替换为开发机 IP，例如：

- `http://10.217.19.22:5174/ui-preview/home`

建议验证尺寸：

- 360px 宽：小屏 Android。
- 375px 宽：iPhone SE / iPhone mini。
- 390px 宽：常见 iPhone。
- 414px-430px 宽：大屏 Android / Pro Max。

## 后续接入原则

静态原型确认后，再进行真实页面改造：

1. 先抽公共样式变量与组件。
2. 再替换 Home、AppealList、MeetingRoomList 的表现层。
3. 保留现有接口、路由守卫、状态机和业务校验。
4. 最后补充加载态、空状态、错误态、长文本和弱网场景。
