# 企业服务中心系统

# 第一阶段数据库与后端接口设计说明

## 一、第一阶段目标

第一阶段不追求页面美化，也不先做复杂统计，重点完成系统底座：

1. 建立统一数据库结构；
2. 建立企业端与管理端两套接口；
3. 建立三大业务模块的基础闭环；
4. 预留企业端省级统一身份认证对接；
5. 预留管理端政务服务平台统一用户体系对接；
6. 建立统一企业档案、附件、评价、消息、日志、字典体系；
7. 为后续微信公众号 H5 前端和 PC 管理端开发提供稳定接口。

第一阶段后端要能支撑：

| 模块    | 第一阶段目标                               |
| ----- | ------------------------------------ |
| 企业诉求  | 提交、受理、退回、不予受理、自办、分派、部门反馈、企服中心审核、企业评价 |
| 共享会议室 | 会议室维护、开放规则、材料上传、预约申请、审核、取消、爽约、台账导出   |
| 政企约见  | 企业申请、审核、退回、不予受理、后台安排、约见记录、约见后评价      |
| 通用能力  | 企业档案、附件、消息、评价、字典、操作日志、用户快照           |

# 二、数据库设计原则

## 2.1 基础原则

数据库设计按以下原则执行：

1. 所有业务表必须带 `region_code`、`region_name` 或 `service_center_id`，支持多区县、多企服中心扩展；
2. 所有业务主表必须带 `enterprise_id`，关联统一企业档案；
3. 所有附件统一进入附件表，不在业务表中直接存文件路径数组；
4. 所有状态类、类型类、原因类字段优先使用字典配置；
5. 所有审核、退回、办理、分派、评价、取消等关键操作都要记录日志；
6. 业务主表只保存当前状态，过程信息进入记录表；
7. 身份认证对接先做适配层，不能把第三方认证逻辑写死在业务代码中；
8. 法人身份证号、手机号等敏感字段需要支持脱敏展示，必要时加密存储；
9. 第一阶段以 MySQL 8 兼容写法为主，字段设计避免强依赖特殊数据库特性；
10. 后续如部署到瀚高数据库，需要通过 ORM 或迁移脚本做兼容适配。

# 八、认证接口设计

---

## 8.1 企业端认证接口

第一阶段先做认证适配层，真实省级统一身份认证暂不写死。

### 1. 省级统一认证回调

```http
POST /api/auth/enterprise/callback
```

用途：

接收省级统一身份认证返回的信息，创建或更新企业档案，并生成企业端 token。

请求参数示例：

```json
{
  "authCode": "认证授权码",
  "state": "状态参数"
}
```

返回：

```json
{
  "token": "enterprise-token",
  "enterprise": {
    "id": 1,
    "enterpriseName": "某某企业有限公司",
    "creditCode": "9137XXXXXXXXXXXXXX"
  }
}
```

第一阶段可先用模拟接口：

```http
POST /api/auth/enterprise/mock-login
```

用于开发联调。

---

### 2. 获取当前企业信息

```http
GET /api/enterprise/me
```

返回当前登录企业信息。

---

## 8.2 管理端认证接口

### 1. 政务服务平台登录回调

```http
POST /api/auth/admin/callback
```

用途：

接收统一用户体系返回的用户信息，生成管理端 token，并写入用户快照。

### 2. 管理端模拟登录

```http
POST /api/auth/admin/mock-login
```

第一阶段用于开发调试。

### 3. 获取当前管理端用户

GET /api/admin/me
```

返回：

{

  "departmentName": "某某部门",

}
```

# 十三、权限控制设计

## 13.1 企业端权限

企业端权限规则：

1. 企业只能查看本企业数据；
2. 企业只能修改本企业处于允许状态的数据；
3. 企业不能访问管理端接口；
4. 企业评价只能评价本企业已完成或已回复的数据；
5. 被限制预约会议室的企业不能提交会议室预约。

| 角色             | 说明       |
| -------------- | -------- |
| PLATFORM_ADMIN | 平台管理员    |
| CITY_ADMIN     | 市级管理员    |
| CENTER_ADMIN   | 企服中心管理员  |
| CENTER_STAFF   | 企服中心工作人员 |
| DEPT_USER      | 部门办理人员   |
| ROOM_ADMIN     | 会议室管理员   |

数据权限：

| 角色             | 数据范围      |
| -------------- | --------- |

| CITY_ADMIN     | 全部        |
| CENTER_ADMIN   | 本区县/本企服中心 |
| CENTER_STAFF   | 本区县/本企服中心 |
